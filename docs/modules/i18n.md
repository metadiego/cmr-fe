# Module: i18n (multi-language)

## Purpose
Multi-language UI (Spanish + English) for the FE. Every visible string comes from per-locale
dictionaries; the active locale is cookie-based (no URL prefix). Default locale: **`es`**.
New code is written with **English keys**.

## Files
- `i18n/config.ts` — `locales = ['es','en']`, `defaultLocale`, `LOCALE_COOKIE` (`NEXT_LOCALE`),
  `isLocale()`, `type Locale`. **Add a language here.**
- `i18n/request.ts` — `getRequestConfig`: reads the cookie (`await cookies()` — Next 16 async),
  loads `messages/<locale>.json`, sets `timeZone` (`America/Mexico_City`) and ICU `formats`.
- `i18n/locale-actions.ts` — `setLocale(locale)` Server Action (writes the cookie, 1 year, lax).
- `messages/es.json`, `messages/en.json` — the dictionaries, namespaced by module.
- `components/language-toggle.tsx` — UI switcher; calls `setLocale` then `router.refresh()`.
- `next.config.ts` — wrapped with `createNextIntlPlugin('./i18n/request.ts')`.
- `app/layout.tsx` — async root; `<html lang={await getLocale()}>` + `<NextIntlClientProvider>`.

## i18n keys (namespaces)
`common`, `language`, `nav`, `landing`, `login`, `dashboard`, `apiHealth`. One namespace per
module/feature. Keys are authored in **English**; `es.json` carries the Spanish text, `en.json`
the English text — same key shape in both.

## How to use
- **Server Component / Server Action:** `const t = await getTranslations('ns'); t('key')`
  (import from `next-intl/server`). Also `getLocale()`, `getFormatter()`.
- **Client Component:** `const t = useTranslations('ns'); t('key')` (import from `next-intl`).
  Also `useLocale()`, `useFormatter()`.
- **Interpolation:** `t('key', { name })` for `{name}` placeholders.
- **Rich text** (embedded tags like `<code>`/`<kbd>`): `t.rich('key', { code: (c) => <code>{c}</code> })`.
- **Formatting (#14):** `const f = useFormatter(); f.dateTime(date, 'short'); f.number(amount, 'currency')`
  (presets defined in `i18n/request.ts`).

## How to add…
- **a string:** add the key to BOTH `messages/es.json` and `messages/en.json`, then `t('key')`.
- **a namespace:** add the object to both JSON files; call `useTranslations('newNs')`.
- **a language:** add the code to `locales` in `i18n/config.ts` and create `messages/<code>.json`.

## BE dependencies
None. Locale is FE-only (cookie). **Future (#51):** `i18n/request.ts` will resolve locale by
precedence *master override → user prefs (BE via `lib/api/`) → cookie → default* — marked `// TODO #51`.

## Decisions
- `next-intl` over native dictionaries (ICU formatting + no forced `[lang]` routing).
- Cookie-based, **no i18n routing** → `proxy.ts` untouched; routes/gating unchanged.
- BE-sourced error messages shown verbatim (not translated).
